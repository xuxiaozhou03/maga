# ETF 计算引擎技术设计文档

**文档名称：** CALCULATION-ENGINE.md  
**产品版本：** V0.6  
**文档状态：** 设计规范  
**适用对象：** Codex、开发人员

---

## 1. 设计目标

计算引擎负责将 ETF 研究池、日 K 行情和指数估值数据转换为每日 ETF 特征数据。

核心目标：

1. 首次运行时支持全量历史计算。
2. 每个交易日生成最新分析结果。
3. 计算 ETF 收益、趋势、风险、成交活跃度和估值特征。
4. 支持日 K 聚合为周 K、月 K。
5. 支持历史行情修正后的关联重算。
6. 支持数据缺失、样本不足和部分计算失败。
7. 输出统一的数据结构，供排名模块和前端使用。

计算引擎不负责：

- ETF 研究池筛选规则。
- ETF 分类规则。
- 综合排名权重。
- 综合评分模型。
- 前端页面展示。
- 行情数据源的具体请求实现。

这些内容分别由其他文档定义。

## 2. 计算输入与输出

### 2.1 输入数据

计算引擎使用以下数据：

| 数据         | 来源         | 用途                       |
| ------------ | ------------ | -------------------------- |
| ETF 研究池   | 研究池模块   | 确定计算对象               |
| ETF 日 K     | 行情采集模块 | 收益、趋势、风险、成交计算 |
| 指数估值     | 估值采集模块 | PE、PB、PS 特征            |
| 分类配置     | 分类配置文件 | 将分类快照写入每日结果     |
| 历史分析结果 | daily JSON   | 历史修正、结果对比和恢复   |

### 2.2 输出数据

计算引擎向后续模块提供：

```text
每日 ETF 特征
├── 行情基础特征
├── 周期收益
├── 收益分布
├── 趋势特征
├── 风险特征
├── 成交活跃度
├── 历史统计
└── 估值特征
```

排名模块读取 ETF 特征，生成全池排名。

最终由结果生成模块组装：

```text
DailyAnalysisResult
├── date
├── generatedAt
├── status
├── summary
├── market
├── etfs
└── task
```

每日结果的最终结构以 `DATA-MODEL.md` 为准。

## 3. 统一计算口径

### 3.1 行情口径

系统只使用前复权日 K。

所有价格相关计算必须基于同一套前复权行情：

- 收益率。
- 移动平均线。
- BOLL。
- 波动率。
- 最大回撤。
- 连涨连跌。
- 新高统计。
- 周 K 和月 K。

不得混用前复权、后复权和不复权行情。

### 3.2 日期口径

- 日期统一使用 `YYYYMMDD` 整数。
- 所有计算均以分析日期为截止日期。
- 不允许使用分析日期之后的数据。
- 非交易日不生成新的 ETF 日特征。
- 周 K、月 K 根据截至分析日期已获得的日 K 聚合。

### 3.3 收益率口径

内部收益率统一使用小数：

| 实际收益率 | 保存值 |
| ---------- | -----: |
| 上涨 1%    |   0.01 |
| 上涨 5%    |   0.05 |
| 下跌 2%    |  -0.02 |
| 下跌 10%   |  -0.10 |

日 K 原始字段 `changePercent` 沿用数据模型约定的百分数口径：

- 上涨 1% 保存为 1。
- 下跌 2% 保存为 -2。

从 K 线计算出的收益率必须转换为小数，不能直接复制 `changePercent`。

### 3.4 成交量和成交额

- `volume`：沿用行情数据源标准化后的成交量单位。
- `amount`：统一为元。
- 所有成交额均使用元计算。
- 缺失成交额使用 null，不得填 0。

### 3.5 缺失值

统一使用 null。

以下情况不能用 0 替代：

- 历史行情不足。
- 当日行情缺失。
- 估值数据缺失。
- 无法计算波动率。
- 无法计算最大回撤。
- 样本数量不足。

0 是有效数值，例如收益率为 0、成交额确实为 0，必须与缺失值区分。

## 4. 行情预处理

### 4.1 K 线排序

进入计算引擎前，所有 ETF 的 K 线必须按日期升序排列。

```ts
const klines = [...input].sort((a, b) => a.date - b.date);
```

### 4.2 数据唯一性

同一 ETF 同一交易日期只能有一条日 K。

如果出现重复记录：

1. 由数据采集层按日期去重。
2. 无法确定有效记录时，将该 ETF 标记为数据异常。
3. 不允许将重复 K 线直接参与计算。

### 4.3 基础数据校验

每条 K 线至少检查：

- code 是否与目标 ETF 一致。
- date 是否有效。
- open、high、low、close 是否为有效正数。
- high 是否不小于 open、close、low。
- low 是否不大于 open、close、high。
- volume、amount 是否为有效数值。
- 是否存在明显异常的日期顺序或重复日期。

异常数据不得静默参与计算。

### 4.4 分析日期行情

对每只 ETF，确定截至分析日期的最新有效交易日。

如果某只 ETF 当日没有 K 线：

- 不得将上一交易日收盘价伪装成当日收盘价。
- `features.close` 和当日涨跌幅根据实际数据情况设置。
- 其他历史特征可以使用最后有效行情计算，但必须保留其实际行情日期。
- 在数据质量状态中明确标记当日行情缺失。

建议在 `EtfFeatures` 中增加：

```ts
data: {
  latestKlineDate: DateNumber | null;
  isLatestKlineCurrent: boolean;
}
```

其中：

- `latestKlineDate`：最新有效 K 线日期。
- `isLatestKlineCurrent`：最新有效 K 线日期是否等于分析日期。

## 5. 周期收益计算

### 5.1 计算周期

系统计算以下周期收益：

| 字段 |         周期 |
| ---- | -----------: |
| d1   |   1 个交易日 |
| d5   |   5 个交易日 |
| d20  |  20 个交易日 |
| d60  |  60 个交易日 |
| d120 | 120 个交易日 |
| d250 | 250 个交易日 |
| ytd  |     年初至今 |

### 5.2 计算公式

设：

- 当前交易日收盘价为 \(C_t\)。
- N 个交易日前收盘价为 \(C\_{t-N}\)。

周期收益：

\[
R*N = \frac{C_t}{C*{t-N}} - 1
\]

例如：

当前收盘价为 1.10，20 个交易日前收盘价为 1.00：

\[
R\_{20} = \frac{1.10}{1.00}-1=0.10
\]

保存值为 0.10，即上涨 10%。

### 5.3 交易日数量

周期按有效交易日计算，不按自然日计算。

例如：

- d5：当前交易日与 5 个交易日前的收盘价比较。
- d20：当前交易日与 20 个交易日前的收盘价比较。
- d250：当前交易日与 250 个交易日前的收盘价比较。

因此，计算 d250 至少需要 251 个有效收盘价。

### 5.4 YTD

YTD 使用当前交易日收盘价与当年首个有效交易日前一个有效交易日的收盘价计算。

\[
R*{YTD} = \frac{C_t}{C*{previousYearEnd}} - 1
\]

如果缺少上一年度最后一个有效交易日的收盘价，则 YTD 为 null。

### 5.5 样本不足

如果缺少对应周期的历史收盘价：

- 对应收益字段为 null。
- 不允许缩短周期后仍然写入原周期字段。
- 不影响其他周期的计算。

## 6. 收益分布计算

### 6.1 日收益率序列

使用相邻有效交易日收盘价计算日收益率：

\[
r*t = \frac{C_t}{C*{t-1}} - 1
\]

### 6.2 统计指标

```ts
interface ReturnDistribution {
  mean: number | null;
  median: number | null;
  stdDev: number | null;
  positiveRatio: number | null;
  negativeRatio: number | null;
}
```

计算定义：

| 指标          | 计算方式              |
| ------------- | --------------------- |
| mean          | 日收益率算术平均值    |
| median        | 日收益率中位数        |
| stdDev        | 日收益率样本标准差    |
| positiveRatio | 日收益率大于 0 的比例 |
| negativeRatio | 日收益率小于 0 的比例 |

日收益率等于 0 时，不计入正收益或负收益数量。

### 6.3 统计窗口

日常特征计算使用最近 20 个有效日收益率作为短期收益分布窗口。

如果不足 20 个有效日收益率：

- mean、median 可以基于实际样本计算，但必须记录样本数。
- stdDev 至少需要 2 个样本。
- 比例指标使用实际有效样本数计算。
- 样本不足时不得伪造完整 20 日统计结果。

建议结构：

```ts
interface ReturnDistribution {
  mean: number | null;
  median: number | null;
  stdDev: number | null;
  positiveRatio: number | null;
  negativeRatio: number | null;
  sampleCount: number;
}
```

## 7. 趋势特征计算

### 7.1 移动平均线

计算周期：

- MA5
- MA10
- MA20
- MA60
- MA120
- MA250

公式：

\[
MA*N = \frac{C_t+C*{t-1}+\cdots+C\_{t-N+1}}{N}
\]

使用最近 N 个有效交易日的收盘价。

样本不足 N 个时，结果为 null。

### 7.2 价格与均线关系

计算：

- `priceAboveMa20`
- `priceAboveMa60`

规则：

```ts
priceAboveMa20 = close !== null && ma20 !== null ? close > ma20 : null;
```

收盘价恰好等于均线时，结果为 false。

### 7.3 均线排列

使用 MA5、MA10、MA20、MA60、MA120、MA250 判断均线排列。

本阶段只输出均线排列状态，不直接生成综合趋势评分。

建议枚举：

```ts
type MaAlignment = "bullish" | "bearish" | "mixed" | "insufficient";
```

定义：

- bullish：所有可参与判断的均线严格按照短周期大于长周期排列，且参与判断的均线不少于 3 条。
- bearish：所有可参与判断的均线严格按照短周期小于长周期排列，且参与判断的均线不少于 3 条。
- mixed：有足够均线数据，但不满足 bullish 或 bearish。
- insufficient：可参与判断的均线少于 3 条。

MA 排列判断只使用有效均线，不得把 null 当成 0。

### 7.4 BOLL 布林带

参数固定：

- 周期：20。
- 标准差倍数：2。

中轨：

\[
MB = MA\_{20}
\]

标准差：

\[
SD*{20} = \sqrt{\frac{\sum*{i=1}^{20}(C*i-MA*{20})^2}{20}}
\]

上轨：

\[
UP = MB + 2 \times SD\_{20}
\]

下轨：

\[
DN = MB - 2 \times SD\_{20}
\]

本系统使用总体标准差，即分母为 20。

### 7.5 BOLL 位置

```ts
bollPosition = (close - bollLower) / (bollUpper - bollLower);
```

解释：

- 0：位于下轨。
- 0.5：位于中轨。
- 1：位于上轨。
- 小于 0：位于下轨以下。
- 大于 1：位于上轨以上。

如果上轨与下轨相等，返回 null。

## 8. 风险特征计算

### 8.1 波动率

计算周期：

- 20 日。
- 60 日。
- 120 日。

先计算每日收益率，再计算样本标准差。

年化波动率：

\[
Volatility_N = StdDev(r) \times \sqrt{250}
\]

其中：

- `StdDev(r)`：对应窗口内日收益率样本标准差。
- 250：统一使用的年化交易日数。

结果使用小数保存。

例如 20% 年化波动率保存为 0.20。

样本不足时返回 null。

### 8.2 最大回撤

计算周期：

- 20 日。
- 60 日。
- 120 日。
- 250 日。

对窗口内每个交易日计算：

\[
DD_t = \frac{C_t}{Peak_t}-1
\]

其中：

\[
Peak_t = \max(C_1,C_2,\ldots,C_t)
\]

最大回撤：

\[
MDD = \min(DD_t)
\]

结果使用负数表示。

例如最大回撤为 -15%，保存为 -0.15。

窗口内价格不足对应周期时，返回 null。

### 8.3 当前回撤

当前回撤使用当前收盘价与截至当前日期的历史最高收盘价计算：

\[
CurrentDD = \frac{C_t}{HistoricalPeak_t}-1
\]

历史最高价必须基于可获得的完整历史数据。

### 8.4 回撤持续时间

`drawdownDuration` 表示当前处于回撤状态的连续有效交易日数。

规则：

- 当前收盘价等于历史最高收盘价时，持续时间为 0。
- 当前收盘价低于历史最高收盘价时，统计从最近一次创出或重新达到历史最高收盘价之后经过的有效交易日数。
- 缺少足够历史数据时返回 null。

## 9. 成交活跃度计算

### 9.1 成交额

记录最新有效交易日成交额：

```ts
amount: number | null;
```

### 9.2 成交额均值

计算：

- 5 日平均成交额。
- 20 日平均成交额。

公式：

\[
AmountMA*N = \frac{\sum*{i=1}^{N}Amount_i}{N}
\]

只使用有效成交额数据。

样本不足时返回 null，并记录实际样本数。

### 9.3 成交额变化

```ts
amountChange =
  amountMA5 !== null && amountMA20 !== null ? amountMA5 / amountMA20 - 1 : null;
```

表示短期成交额相对中期成交额的变化比例。

### 9.4 成交额倍数

```ts
amountRatio =
  amountMA5 !== null && amountMA20 !== null && amountMA20 > 0
    ? amountMA5 / amountMA20
    : null;
```

解释：

- 大于 1：近期成交额高于 20 日平均水平。
- 小于 1：近期成交额低于 20 日平均水平。
- 等于 1：近期成交额接近 20 日平均水平。

## 10. 历史统计指标

历史统计用于观察 ETF 在不同时间区间的表现。

### 10.1 统计周期

统一统计：

| 周期     | 交易日参考数 |
| -------- | -----------: |
| 近 1 月  |           20 |
| 近 3 月  |           60 |
| 近 6 月  |          120 |
| 今年以来 |          YTD |
| 近 1 年  |          250 |
| 近 2 年  |          500 |

这里的交易日数量用于收益和风险指标计算，不是自然日数量。

### 10.2 统计结构

```ts
interface HistoricalPeriodStatistics {
  effectiveDays: number;

  cumulativeReturn: number | null;
  annualizedReturn: number | null;

  volatility: number | null;
  maxDrawdown: number | null;

  sharpeRatio: number | null;
  sortinoRatio: number | null;
  calmarRatio: number | null;

  positiveDays: number;
  negativeDays: number;
  flatDays: number;

  maxConsecutiveUpDays: number;
  maxConsecutiveDownDays: number;

  highestClose: number | null;
  lowestClose: number | null;

  averageAmount: number | null;
}

interface HistoricalStatistics {
  month1: HistoricalPeriodStatistics;
  month3: HistoricalPeriodStatistics;
  month6: HistoricalPeriodStatistics;
  ytd: HistoricalPeriodStatistics;
  year1: HistoricalPeriodStatistics;
  year2: HistoricalPeriodStatistics;
}
```

### 10.3 有效交易日数

`effectiveDays` 表示该统计区间内参与计算的有效日收益率数量。

不包括缺失行情和无效行情。

### 10.4 累计收益

使用区间首个交易日前一个有效收盘价作为基准：

\[
CumulativeReturn = \frac{C*{end}}{C*{start}}-1
\]

缺少基准收盘价时返回 null。

### 10.5 年化收益

对于非 YTD 周期：

\[
AnnualizedReturn =
(1+CumulativeReturn)^{250/N}-1
\]

其中 N 为有效收益率数量。

对于 YTD：

\[
AnnualizedReturn =
(1+CumulativeReturn)^{250/D}-1
\]

其中 D 为当年截至分析日期的有效交易日数量。

如果累计收益小于或等于 -100%、有效交易日数不足或计算结果无效，返回 null。

年化收益仅用于统计比较，不代表未来预期收益。

### 10.6 年化波动率

使用区间内日收益率样本标准差：

\[
Volatility = StdDev(r)\times\sqrt{250}
\]

至少需要 2 个有效日收益率。

### 10.7 Sharpe Ratio

无风险利率在 V0.6 固定为 0。

\[
SharpeRatio =
\frac{Mean(r)}{StdDev(r)}\times\sqrt{250}
\]

要求：

- 至少有 2 个有效日收益率。
- 标准差必须大于 0。
- 不满足条件时返回 null。

### 10.8 Sortino Ratio

下行风险使用日收益率低于 0 的部分计算。

\[
DownsideDeviation =
\sqrt{\frac{\sum \min(r_i,0)^2}{N}}
\]

\[
SortinoRatio =
\frac{Mean(r)}{DownsideDeviation}\times\sqrt{250}
\]

如果下行偏差为 0，返回 null。

### 10.9 Calmar Ratio

\[
CalmarRatio =
\frac{AnnualizedReturn}{|MaxDrawdown|}
\]

最大回撤为 0 或缺失时返回 null。

### 10.10 连涨连跌

根据相邻有效交易日收益率判断：

- 正收益：上涨日。
- 负收益：下跌日。
- 零收益：平盘日。

统计区间内：

- 最大连续上涨天数。
- 最大连续下跌天数。

平盘日会中断上涨或下跌连续计数。

### 10.11 最高和最低收盘价

统计区间内：

- `highestClose`：最高收盘价。
- `lowestClose`：最低收盘价。

不使用最高价和最低价字段代替收盘价统计。

### 10.12 平均成交额

统计区间内有效成交额的算术平均值。

缺失成交额不参与平均值计算。

## 11. 周 K 和月 K 计算

### 11.1 周 K

以自然周为周期，按照交易日数据聚合。

例如：

周二运行任务时，如果本周只有周一、周二两条日 K，则使用这两条数据生成当前周 K。

字段计算：

| 字段   | 计算方式                      |
| ------ | ----------------------------- |
| open   | 本周第一条有效日 K 的 open    |
| high   | 本周最高 high                 |
| low    | 本周最低 low                  |
| close  | 本周最后一条有效日 K 的 close |
| volume | 本周有效 volume 合计          |
| amount | 本周有效 amount 合计          |
| date   | 本周最后一个有效交易日        |

### 11.2 月 K

以自然月为周期。

字段计算方式与周 K 相同。

### 11.3 当前周期

当前周和当前月不需要等待周期结束。

只使用截至分析日期已经获得的日 K。

### 11.4 使用范围

周 K 和月 K 用于趋势观察和后续研究。

V0.6 不要求单独保存周 K、月 K 历史文件。

## 12. 估值特征计算

估值数据按指数代码关联，不按 ETF 代码独立采集。

### 12.1 关联规则

```text
ETF.trackIndex
      ↓
IndexValuation.code
```

同一跟踪指数的 ETF 使用同一份指数估值数据。

### 12.2 PE、PB、PS

分别获取：

- PE。
- PB。
- PS。

三种估值独立计算、独立记录。

### 12.3 估值日期

估值记录必须满足：

```text
valuation.date <= analysisDate
```

不得使用未来估值数据。

### 12.4 最新估值

每种估值类型分别选择不晚于分析日期的最新有效记录。

### 12.5 估值滞后天数

```ts
lagDays = analysisDate - valuationDate;
```

这里的滞后天数按自然日计算。

如果估值记录日期缺失或无法解析，相关估值特征返回 null。

### 12.6 历史百分位

直接使用上游近五年历史百分位。

上游百分数转换为 0～1 小数后保存。

例如：

- 上游 73.76。
- 内部保存 0.7376。

本阶段不重新计算其他时间周期的估值百分位。

### 12.7 估值缺失

PE、PB、PS 任何一种缺失：

- 对应字段设置为 null。
- 不影响另外两种估值。
- 记录数据质量状态。
- 不允许用 0 填充。

## 13. 特征计算总览

每只 ETF 每个分析日必须尝试生成以下特征：

| 类别     | 指标                               |
| -------- | ---------------------------------- |
| 行情     | 最新收盘价、当日涨跌幅             |
| 收益     | 1、5、20、60、120、250 日收益、YTD |
| 收益分布 | 均值、中位数、标准差、涨跌比例     |
| 趋势     | MA5、10、20、60、120、250          |
| 趋势     | 价格与 MA20、MA60 关系             |
| 趋势     | 均线排列                           |
| 趋势     | BOLL20,2 上中下轨及位置            |
| 风险     | 20、60、120 日波动率               |
| 风险     | 20、60、120、250 日最大回撤        |
| 风险     | 当前回撤、回撤持续时间             |
| 成交     | 成交额、5 日和 20 日平均成交额     |
| 成交     | 成交额变化、成交额倍数             |
| 历史统计 | 1 月、3 月、6 月、YTD、1 年、2 年  |
| 估值     | PE、PB、PS 及其历史百分位          |

不得因为某个指标无法计算而放弃整只 ETF 的其他指标。

## 14. 全量计算与每日增量计算

### 14.1 首次全量计算

首次运行时：

1. 读取 ETF 研究池。
2. 获取研究池内所有 ETF 的历史日 K。
3. 获取研究池涉及的唯一指数代码。
4. 获取各指数 PE、PB、PS 估值历史。
5. 校验和标准化数据。
6. 按分析日期计算所有 ETF 特征。
7. 生成全池排名所需的特征输入。
8. 生成市场概览。
9. 生成每日完整分析结果。
10. 保存每日结果和 current.json。

首次计算必须以全池为单位。

不能只计算当天新增 ETF，而忽略其他 ETF。

### 14.2 每日计算

每日任务执行时：

1. 检查最新分析日期。
2. 更新研究池。
3. 获取研究池 ETF 最新日 K。
4. 检查是否存在历史行情修正。
5. 更新指数估值数据。
6. 计算所有 ETF 的最新特征。
7. 重新计算全池排名输入。
8. 重新计算市场概览。
9. 生成每日完整结果。
10. 保存每日结果。

每日任务生成完整的全池快照。

V0.6 不要求只计算变化 ETF，也不要求构建复杂的局部增量依赖图。

### 14.3 非交易日

非交易日不生成新的交易日分析快照。

如果当天没有新的交易行情：

- 不重复生成同一交易日的历史快照。
- 不将非交易日日期伪装成分析交易日。
- 可以执行数据检查，但不能因此覆盖已有交易日结果。

## 15. 历史行情修正

### 15.1 修正规则

前复权历史行情可能因分红、拆分或数据源更新发生变化。

如果发现历史 K 线被修正，不能只重算当天。

### 15.2 修正检测

对比本次获取的历史行情与上次已使用的数据。

比较字段：

- open
- high
- low
- close
- volume
- amount
- change
- changePercent

发现历史记录变化时，记录：

```ts
interface KlineRevision {
  code: string;
  date: DateNumber;
  changedFields: string[];
  detectedAt: string;
}
```

### 15.3 重算范围

如果 ETF 在日期 T 的历史 K 线发生修正：

1. 从 T 开始重新计算该 ETF 后续所有受影响日期的特征。
2. 重新计算这些日期对应的全池排名。
3. 重新计算这些日期的市场概览。
4. 更新对应日期的历史结果。
5. 如果最新结果受到影响，更新 current.json。

收益、移动平均线、波动率、回撤和历史统计均可能受到历史行情修正影响。

### 15.4 研究池变化

如果 ETF 被新增或移出研究池：

- 新增 ETF：从可用历史行情开始计算。
- 移出 ETF：从新的每日研究池中移除。
- 不得删除已经生成的历史快照。
- 当前排名必须使用当前研究池重新计算。
- 历史排名仍然保留当日研究池口径。

### 15.5 分类变化

分类只影响展示和分类统计。

分类变更：

- 不触发 ETF 特征重算。
- 不触发全池排名重算。
- 只影响后续每日快照中的分类映射。
- 历史每日结果保留当时的分类快照。

## 16. 计算任务状态和异常处理

### 16.1 ETF 级计算状态

建议定义：

```ts
interface EtfCalculationStatus {
  code: string;
  status: "success" | "partial" | "failed";
  warnings: string[];
}
```

### 16.2 部分成功

以下情况允许生成部分结果：

- ETF K 线缺失。
- PE 缺失。
- PB 缺失。
- PS 缺失。
- 某些长期周期样本不足。
- 部分技术特征无法计算。

只要仍然可以生成合法的每日结果，就应尽可能保留有效数据。

### 16.3 失败

以下情况属于任务级失败：

- 研究池无法获取且没有可用的合法历史研究池快照。
- 输入数据结构无法解析。
- 核心计算流程发生未处理异常。
- 无法生成合法每日结果。
- 无法完成必要的文件写入。

失败时不得将空结果覆盖已有 current.json。

### 16.4 可追踪性

每次任务至少记录：

- 任务开始时间。
- 任务结束时间。
- 分析日期。
- 研究池 ETF 数量。
- 成功计算数量。
- 部分成功数量。
- 失败数量。
- 行情修正数量。
- 警告信息。
- 最终任务状态。

## 17. 计算模块建议

建议采用以下模块：

```text
src/
├── calculation/
│   ├── index.ts
│   ├── return-calculator.ts
│   ├── distribution-calculator.ts
│   ├── trend-calculator.ts
│   ├── risk-calculator.ts
│   ├── activity-calculator.ts
│   ├── statistics-calculator.ts
│   ├── period-kline-calculator.ts
│   ├── valuation-calculator.ts
│   └── etf-feature-calculator.ts
│
├── ranking/
│   └── ...
│
├── market/
│   └── ...
│
└── shared/
    └── ...
```

模块职责：

| 模块                    | 职责                            |
| ----------------------- | ------------------------------- |
| return-calculator       | 周期收益和日收益率              |
| distribution-calculator | 收益分布                        |
| trend-calculator        | MA、均线排列、BOLL              |
| risk-calculator         | 波动率、回撤                    |
| activity-calculator     | 成交额和成交活跃度              |
| statistics-calculator   | 历史统计                        |
| period-kline-calculator | 周 K、月 K 聚合                 |
| valuation-calculator    | 指数估值关联和特征              |
| etf-feature-calculator  | 组合各类特征，输出 ETF 特征对象 |

计算函数尽量设计为纯函数：

- 输入明确。
- 输出明确。
- 不直接读写文件。
- 不直接请求网络。
- 相同输入得到相同输出。

## 18. 计算性能与数据使用

V0.6 研究池规模较小，优先保证计算正确性和可维护性。

要求：

1. 同一 ETF 的历史行情在一次任务中只加载一次。
2. 同一指数的估值数据只加载一次。
3. 同一 ETF 的均线、收益和风险计算尽量复用已加载数据。
4. 不要为每个指标重复请求行情。
5. 不要求引入数据库、缓存服务或分布式计算。
6. 不要求引入复杂的并行任务调度。
7. 数据计算与文件读写分离。

历史行情可以在单次计算任务中保存在内存中。

不要求长期保存完整日 K 历史。

## 19. 验收标准

### 19.1 收益计算

- 能正确计算 1、5、20、60、120、250 日收益。
- 能正确计算 YTD。
- 样本不足时返回 null。
- 不混淆百分数和小数。

### 19.2 趋势计算

- 能计算 MA5、10、20、60、120、250。
- 能计算价格与 MA20、MA60 的关系。
- 能判断均线排列。
- 能计算 BOLL20,2。
- BOLL 位置计算正确。

### 19.3 风险计算

- 能计算 20、60、120 日年化波动率。
- 能计算 20、60、120、250 日最大回撤。
- 能计算当前回撤。
- 能计算回撤持续时间。
- 不把缺失数据当成 0。

### 19.4 成交和历史统计

- 能计算 5 日、20 日平均成交额。
- 能计算成交额变化和倍数。
- 能计算近 1 月、3 月、6 月、YTD、1 年、2 年统计。
- 能计算 Sharpe、Sortino、Calmar。
- 能正确处理样本不足。

### 19.5 周 K 和月 K

- 能正确聚合 OHLC。
- 能正确累计成交量和成交额。
- 当前未结束周期可以正常计算。
- 不使用未来数据。

### 19.6 历史修正

- 能识别历史行情变化。
- 能从最早受影响日期向后重算。
- 能更新受影响的历史分析结果。
- 能更新受影响的全池排名和市场概览。
- 不破坏未受影响的历史结果。

### 19.7 数据质量

- 单只 ETF 计算失败不影响其他 ETF。
- 单个估值类型失败不影响其他估值类型。
- 任务状态准确。
- 不产生非法 JSON 数值。
- 失败时不覆盖已有有效结果。
