# ETF 日线行情数据规范与模拟账户回测规则

**文档版本：** V1.0

**适用范围：** A 股 ETF 日线行情、技术指标计算、策略信号生成、模拟账户交易、历史回测与策略可视化。

## 1. 核心设计原则

系统必须区分以下三类数据：

1. **原始行情数据**：数据源提供的原始 OHLC 价格及相关字段。
2. **复权行情数据**：通过原始价格和累计复权因子计算得到的统一前复权价格。
3. **账户交易数据**：模拟账户实际成交、现金变动、持仓变化、交易费用及资产估值。

原始行情不得被复权计算覆盖。复权行情用于技术指标和历史价格分析；原始收盘价用于模拟成交和账户持仓估值。

回测的核心产物是模拟账户、订单、成交、持仓和每日账户快照。收益率、最大回撤等指标均从账户资产记录中计算，不直接通过 `changePercent` 逐日复利得到。

## 2. CSV 字段定义

CSV 第一行为字段名，共 12 个字段。

| 字段            | 类型          | 定义                                                 |
| --------------- | ------------- | ---------------------------------------------------- |
| `date`          | string        | 交易日期，格式 `YYYYMMDD`                            |
| `preClose`      | number        | 当日涨跌幅计算使用的前收盘参考价                     |
| `open`          | number        | 原始开盘价                                           |
| `high`          | number        | 原始最高价                                           |
| `low`           | number        | 原始最低价                                           |
| `close`         | number        | 原始收盘价                                           |
| `volume`        | number        | 成交量，单位沿用数据源定义                           |
| `amount`        | number        | 成交额，单位沿用数据源定义                           |
| `changePercent` | number        | 相对于 `preClose` 的涨跌幅，单位为百分数             |
| `changeAmount`  | number        | `close - preClose`                                   |
| `shares`        | number / null | 数据源提供的份额相关数据，不作为账户持仓数量         |
| `factor`        | number / null | 累计复权因子；非空记录更新因子，空值沿用最近有效因子 |

日期必须能够解析、不得重复，并按升序排列。系统不得人为生成周末、法定节假日等非交易日行情。

## 3. 累计复权因子的处理规则

### 3.1 因子定义

本系统将 CSV 中的 `factor` 作为累计复权因子使用。

设：

- \(F_t\)：第 \(t\) 个交易日生效的累计复权因子。
- \(F\_{\text{latest}}\)：当前行情数据区间最后一个交易日生效的累计复权因子。
- \(P_t^{raw}\)：第 \(t\) 日原始价格。
- \(P_t^{adj}\)：第 \(t\) 日前复权价格。

系统采用以下规则：

1. 按交易日期升序处理行情。
2. 当 `factor` 有有效数值时，更新当前生效因子。
3. 当 `factor` 为空时，沿用最近一次有效因子。
4. 有效因子必须为有限正数。
5. 第一条记录之前没有有效因子时，数据集校验失败，不得自动将因子补为 1。
6. 原始 `factor` 字段必须保留；填充后的有效因子存储在独立字段 `effectiveFactor` 中。

### 3.2 前复权价格公式

统一使用数据区间最后一个有效因子作为复权基准：

\[
P*t^{adj}=P_t^{raw}\times\frac{F_t}{F*{\text{latest}}}
\]

该公式分别应用于原始 `open`、`high`、`low`、`close`：

- `adjOpen`
- `adjHigh`
- `adjLow`
- `adjClose`

不得只调整收盘价，也不得将原始 OHLC 直接当作前复权价格。

### 3.3 因子变化校验

相邻交易日的参考前收盘价采用以下关系进行校验：

\[
preClose*t\approx
\frac{close*{t-1}\times F\_{t-1}}{F_t}
\]

其中，\(F\_{t-1}\) 和 \(F_t\) 均为经过空值延续处理后的有效因子。

如果新旧因子相同，该公式退化为前一交易日原始收盘价与当日 `preClose` 的近似相等关系。

校验必须考虑原始价格精度和参考价格的舍入误差。超出容差时，输出日期、前一日收盘价、前一日有效因子、当日有效因子、实际 `preClose`、预期 `preClose` 和误差。

因子变化用于确定历史价格调整比例，不得仅凭因子变化就推断具体发生了分红、拆分或其他公司行为。

## 4. 复权数据与未来信息隔离

历史全区间前复权价格使用最后一个交易日的有效因子作为基准。

该序列用于历史图表展示和技术指标计算时，必须明确数据区间与基准日期。新增行情可能改变全区间的复权基准，因此重新生成复权序列时需要记录数据版本。

为防止未来数据泄漏，回测中遵守以下规则：

1. 不使用未来交易日的行情或因子更新生成当日可用信号。
2. 对均线交叉、布林带等相对价格指标，使用一致的复权 OHLC 计算。
3. 绝对价格阈值必须明确其复权基准，不得混用不同基准下的价格。
4. 若扩展行情区间后复权基准变化，应重新计算相关指标，并检查历史信号是否发生变化。
5. 当复权基准仅对全部历史价格乘以同一正数时，基于比例关系的指标信号应保持不变；不具备这一性质的策略必须单独验证。

## 5. 行情数据校验

每次加载数据必须执行以下检查：

### 5.1 基础校验

- 字段数量和字段名符合规范。
- 日期合法、无重复、按升序排列。
- `open`、`high`、`low`、`close` 均为有限正数。
- `low <= open <= high`。
- `low <= close <= high`。
- `volume`、`amount` 能够解析为有效数值或符合数据源约定的缺失值。
- `factor` 为空时不转换为零。
- `factor` 有数值时必须为有限正数。

### 5.2 参考价格校验

涨跌幅候选计算公式：

\[
changePercent_t\approx
\left(\frac{close_t}{preClose_t}-1\right)\times100
\]

涨跌额候选计算公式：

\[
changeAmount_t\approx close_t-preClose_t
\]

两项校验均考虑字段精度和舍入误差。

### 5.3 复权校验

- 验证因子空值延续规则。
- 验证每次因子变化与 `preClose` 的关系。
- 验证前复权 OHLC 使用同一调整比例。
- 验证调整后 OHLC 的高低价关系仍然成立。
- 输出所有异常记录，不得静默修正。

`shares` 不得用于推断模拟账户持仓数量。其业务含义、单位和统计口径未经过数据源说明时，不参与账户记账。

## 6. 策略信号与成交时点

本系统采用日线策略、只做多、按原始收盘价模拟成交。

为了避免未来数据泄漏，默认执行时序为：

1. 第 \(t\) 日收盘后，读取截至第 \(t\) 日可用的行情。
2. 计算指标并生成目标仓位或交易信号。
3. 将订单提交至第 \(t+1\) 个交易日的模拟执行流程。
4. 在第 \(t+1\) 日收盘时，按照原始收盘价模拟成交。
5. 成交完成后更新账户账本，并记录当日账户快照。

若需要模拟收盘后交易并按当日收盘价成交，必须单独定义该执行模式及其可行性假设，不能直接将使用当日最终收盘数据生成的信号无条件回填到同一收盘价成交。

所有回测记录必须能够区分信号日期、订单日期、成交日期和成交价格。

## 7. 模拟账户记账

### 7.1 初始状态

账户创建时明确设置：

- 初始现金。
- 初始持仓。
- 交易费用规则。
- ETF 交易单位规则。
- 订单数量规则。
- 成交价格规则。

默认初始持仓为零，全部初始资金作为可用现金。

### 7.2 买入记账

对于买入数量 \(Q\)、原始收盘成交价 \(P\) 和买入费用 \(C_b\)：

\[
买入金额=Q\times P
\]

\[
买入后现金=买入前现金-QP-C_b
\]

买入前必须验证可用资金、交易单位及其他订单约束。资金不足时，不得允许现金变为负数；按系统订单优先级跳过无法满足的订单。

### 7.3 卖出记账

对于卖出数量 \(Q\)、成交价 \(P\) 和卖出费用 \(C_s\)：

\[
卖出净收入=QP-C_s
\]

\[
卖出后现金=卖出前现金+QP-C_s
\]

卖出数量不得超过可卖持仓。默认不允许做空。

### 7.4 持仓估值

每个交易日收盘后：

\[
持仓市值=持仓数量\times原始收盘价
\]

\[
账户总资产=可用现金+持仓市值
\]

如果系统存在冻结资金等额外账户项，应将其纳入账户模型，避免重复计算。

### 7.5 盈亏分类

系统分别记录：

- **已实现盈亏**：已卖出部分对应的盈亏。
- **浮动盈亏**：当前未平仓持仓的估值盈亏。
- **累计费用**：所有已发生交易费用的累计金额。
- **账户总资产变化**：账户总资产相对于初始资产或前一交易日的变化。

已实现盈亏、浮动盈亏与账户资产变化必须分别计算，不能相互替代。

### 7.6 持仓成本

采用移动平均成本法时：

- 买入后，按买入金额及买入费用更新剩余持仓的平均成本。
- 部分卖出时，按卖出数量对应的平均持仓成本计算已实现盈亏。
- 卖出费用计入本次卖出的已实现盈亏。
- 全部清仓后，持仓数量和持仓成本归零。
- 后续重新买入时重新建立持仓成本。

系统必须固定成本核算方法，并在所有策略之间保持一致。

## 8. 公司行为处理

原始价格调整和账户公司行为处理是两个不同层次。

当前版本不自动将因子变化转换成账户分红、份额变化或其他公司行为。

当账户持仓跨越相关公司行为日期时：

- 若系统未实现对应的公司行为处理，应将该日期标记为需要关注。
- 不得仅通过复权价格修改账户现金或持仓数量。
- 不得将无法解释的资产变化直接归因于策略盈亏。
- 正式评估受相关事件影响的账户结果前，必须实现对应的账户处理规则，或明确排除相关区间。

## 9. 账户快照与交易流水

每个交易日必须生成账户快照，即使当天没有成交。

账户快照至少包括：

- 日期。
- 可用现金。
- 持仓数量。
- 持仓市值。
- 持仓成本。
- 已实现盈亏。
- 浮动盈亏。
- 当日交易费用。
- 累计交易费用。
- 账户总资产。
- 账户资产峰值。
- 当前回撤。
- 当日操作类型。
- 关联订单与成交记录。

订单和成交流水至少记录订单 ID、策略 ID、ETF 代码、方向、数量、价格、费用、信号日期、订单日期、成交日期、成交状态和拒绝原因。

## 10. 策略评估与可视化

策略的正式评估以模拟账户账本为数据来源。

### 10.1 账户总览

展示初始资金、当前总资产、可用现金、持仓市值、持仓数量、已实现盈亏、浮动盈亏和累计费用。

### 10.2 账户资产曲线

展示账户总资产、可用现金和持仓市值随时间的变化，并提供回撤曲线。

### 10.3 K 线与交易标记

展示原始 K 线或复权 K 线，明确标注价格类型；显示买卖标记、成交价格、数量、交易费用和交易原因。

### 10.4 交易流水

支持查询每笔交易前后的现金、持仓数量、持仓成本、已实现盈亏和账户总资产。

### 10.5 策略比较

在相同初始资金、费用规则、成交规则和数据区间下，比较不同策略账户及买入持有基准账户。

评估指标包括最终资产、资产回撤、交易次数、费用、持仓时间、现金闲置时间及不同市场阶段的表现。

收益率、年化收益率和夏普比率可以作为辅助指标，但不能替代账户账本和交易流水。

## 11. 回测执行验收条件

只有满足以下条件，数据集才能进入正式回测：

1. CSV 结构和日期顺序校验通过。
2. 原始 OHLC 不被覆盖。
3. 有效因子序列构建成功。
4. 复权价格计算成功。
5. 因子变化与 `preClose` 校验结果可追溯。
6. 所有订单遵守交易单位、资金和持仓约束。
7. 信号时点与成交时点没有未来数据泄漏。
8. 每笔成交都能在账户流水中追溯。
9. 每日账户总资产可以由现金和持仓市值重新计算得到。
10. 交易费用已纳入账户记账。
11. 公司行为未覆盖的风险已明确标注。
12. 策略比较使用一致的账户、成交和费用规则。

**最终约定：** 原始行情用于成交与估值，累计复权因子用于构造前复权行情，策略信号基于明确版本的指标数据生成，模拟账户按照真实的交易流水进行记账。所有结果必须能够从原始数据、订单、成交和账户快照完整追溯。
